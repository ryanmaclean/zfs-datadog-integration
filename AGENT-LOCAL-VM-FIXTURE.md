# Agent-local disposable VM fixture contract

This isolated source copy does **not** contain an admitted runnable Agent/VM integration fixture. Its three former VM test entrypoints and three higher-level VM setup/orchestration entrypoints fail with status 78, and the five Linux ZFS Packer templates fail in their first shell provisioner before ZFS provisioning. This is deliberate until the requirements below are implemented and reviewed. A green direct HTTP mock or successful UDP write is not Agent receive/forward or Datadog intake proof.

## Required input before reopening an image build

1. Pin the exact VM image bytes and checksum, boot only a disposable guest on an approved off-i9 executor, and prove the target guest ID and scratch disks cannot name a live NAS or existing pool. The current Packer templates have `iso_checksum = "none"` or equivalent unreviewed image identity; do not use that as a production-image provenance claim.
2. Select an unmodified, version-pinned Datadog Agent **package** for the exact guest OS/architecture. Record the repository signature or artifact digest, complete selected binary/runtime/dependency notices, and an independent MIT/BSD/Apache-2.0 product-license decision. The Agent repository's general Apache-2.0 label alone does not cover every packaged component; GPL BPF and outside-list components must not be selected. Do not vendor, fork, rebuild a substitute Agent, or substitute a UDP stub as the Agent.
3. Install and activate the reviewed package through its supported guest service route. Prove the Agent's DogStatsD endpoint is loopback-only at `127.0.0.1:8125`, that the active process owns it, and that package/service identity remains stable throughout the fixture. The ZED payload must contain no Datadog API key and no direct HTTP sender.
4. Run the already guarded, hash-pinned installer from a root-owned sealed source directory. Read back installed file hashes, ownership, single ZED route per event class, and active ZED service. Configure only through the reviewed payload **before** sealing/installing; never stop ZED to overwrite `/etc/zfs/zed.d/config.sh` afterward.
5. In the disposable guest only, create a bounded file-backed test pool with an explicit absent-name and scratch-disk preflight. Trigger one real scrub event and one representative error-class event safely. Correlate the unique ZFS event ID, exactly one handler invocation, Agent receive and Forwarder evidence, and time-bounded matching Datadog event **and metric** readbacks. A local Agent socket write is a handoff attempt, not proof that the Agent parsed or forwarded it.
6. Exercise bounded Agent/ZED restart, socket loss and duplicate-event cases; record whether failures propagate, whether finish handlers still clear gauges, and whether any event was lost or duplicated. Capture host/tool/package versions, command exits and redacted logs. Do not put an API key in the image, script arguments, environment dump, or receipt. If an intake key is needed, inject it only into the disposable guest through a reviewed protected runtime path and remove it after the fixture.
7. Destroy only the fixture-owned pool/files and guest after independent evidence readback. Never target QNAS, QNAS2, i9, or any real ZFS array. Any failed preflight or ambiguous target aborts before pool/service mutation.

## Current route decision

The frozen candidate tree supplies loopback DogStatsD ZED sender source but no packaged Agent install/activation in the five Linux Packer templates. The prior VM scripts used a direct HTTP mock, asserted its `/status`, and rewrote sealed ZED config after installation. No exact package archive, signature, selected-license graph, Agent service fixture, runtime receipt, or matching intake readback is present in this copy or the inspected PR20 receipts. Therefore the package route is **unproved** and the image gate stays closed. The first source change to reopen it must add a reviewed package/version gate and actual Agent-local fixture, then replace the unconditional early Packer failure; changing only the failure string cannot establish acceptance.
